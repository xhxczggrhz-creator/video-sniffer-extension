# 国际化（i18n）指南 / Internationalization Guide

本项目使用 **Chrome 原生语言包机制**，没有自建 i18n 框架、没有构建步骤、没有第三方依赖。

This project uses Chrome's **built-in message catalogs**. There is no custom i18n framework,
no build step, and no third-party dependency.

---

## 它是怎么工作的 / How it works

| 位置 | 作用 |
|---|---|
| `_locales/zh_CN/messages.json` | 默认语言包（`manifest.json` 的 `default_locale`），中文原文的唯一来源 |
| `_locales/en/messages.json` | 英文语言包 |
| `lib/i18n.js` | 极薄的 `t(key, subs)` 封装，内部就是 `chrome.i18n.getMessage` |
| `manifest.json` | 名称/简介/弹窗标题用 `__MSG_ext_name__` 这类占位符 |

Chrome 会按用户的**界面语言**自动挑选语言包；某个语言包缺少某个键时，会自动回落到
`default_locale`（zh_CN）。因此：**漏翻译永远不会让界面出现空白**。

Chrome picks the catalog that matches the user's **UI language**. If a catalog is missing a
key, Chrome falls back to `default_locale` (zh_CN). A missing translation therefore never
renders an empty string.

`lib/i18n.js` 还做了两层兜底：

1. `t()` 拿不到译文时返回**键名本身**（开发期一眼可见）；
2. HTML 里写死的中文原文保留不动，`data-i18n` 只在有译文时覆盖它 —— 所以语言包损坏
   或脚本未加载时，界面依然可读。

## 在代码里用 / Using it in code

```js
// 直接取文案
t('dl_speed');                       // "速度" / "Speed"

// 带变量：$1、$2… 对应 subs 数组
t('popup_found_count', [3]);         // "已检测到 3 个视频" / "3 video(s) found"

// 自定义兜底（一般不需要）
tOr('dl_speed', '速度');
```

HTML 只需加属性，**中文原文照旧留在标签里**（它就是无 JS 兜底）：

```html
<h3 data-i18n="dl_settings_title">下载设置</h3>
<input data-i18n-placeholder="popup_search_placeholder" placeholder="搜索视频…">
<button data-i18n-title="popup_rescan_title" title="重新扫描页面">…</button>
```

支持的属性：`data-i18n`（textContent）、`data-i18n-title`、`data-i18n-placeholder`、
`data-i18n-aria-label`。`lib/i18n.js` 在 DOM 就绪后自动替换（`VSI18N.localizeDom()`）。

### 三类文件怎么接上 `t`

| 上下文 | 接入方式 |
|---|---|
| 扩展页面（popup / download-page / offscreen） | `<script src="../lib/i18n.js"></script>` 放在其它脚本**之前**，之后直接用全局 `t` |
| Service Worker（ES Module） | `import '../lib/i18n.js';` 然后 `const t = globalThis.VSI18N.t;` |
| 隔离世界内容脚本 | `lib/i18n.js` 已列入 `manifest.json` 的 `content_scripts` |
| `lib/*.js`（页面 + Node 单测共用） | 顶部加兜底：`var t = (typeof globalThis.t === 'function') ? globalThis.t : ((k) => k);`（**必须是 `var`**，多个经典脚本共享全局作用域，两个顶层 `const t` 会直接报重复声明） |

## 键名规范 / Key naming

`<区域>_<简短英文小写下划线>`，区域前缀固定，避免不同文件撞名：

| 前缀 | 文件 |
|---|---|
| `ext_` | `manifest.json` |
| `popup_` | `popup/` |
| `dl_` | `download-page/` |
| `sw_` | `background/service-worker.js` |
| `cs_` | `content/content-script.js`、`content/media-sniffer.js` |
| `de_` / `sd_` / `nh_` | `lib/download-engine.js` / `lib/stream-downloader.js` / `lib/net-helpers.js` |
| `off_` | `offscreen/` |

**消息里的 `$` 是保留字符**：变量用 `$1`…`$9`，要输出字面量 `$` 必须写成 `$$`。

## 新增一门语言 / Adding a language

1. 复制 `_locales/en/` 为 `_locales/<BCP-47 代码>/`（如 `ja`、`de`、`pt_BR`）。
   可用的目录名见 [Chrome 支持的 locale 列表](https://developer.chrome.com/docs/extensions/reference/api/i18n#locales)。
2. 翻译 `messages.json` 里每个 `message` 的**值**。**不要**改键名，**不要**少键。
3. 跑门禁：

   ```bash
   npm run test:i18n
   ```

   它会校验：键集合与 zh_CN 一致、`$n` 占位符一致、代码引用的键都存在、
   `manifest.json` 的 `__MSG_*__` 都存在。

4. 不需要改任何代码 —— 打包与 CI 已包含整个 `_locales` 目录。

**注意**：不必逐字直译。`ext_desc` 有 132 字符上限（Chrome 商店限制），
按钮文案尽量短（`.btn-label` 是窄条按钮，中文 2-4 字 / 西文 1-2 个词最合适）。

## 已知边界 / Known limits

刻意为中文、**不要翻译**的部分：

- 代码注释与 `console.*` 调试输出（面向维护者，不是用户）；
- `content/mse-hook.js` 与 `lib/mp4-merger.js`（运行在页面 **MAIN world**，那里没有
  `chrome.i18n`）；
- `lib/ts-remux.js` 的内部错误码；
- 站点自身返回的数据（清晰度标记 `1080p`/`HDR`、格式名、文件名）。

`manifest.json` 里的 `dns` 权限与 `SECURITY.md` 描述的已知安全边界与语言无关。
